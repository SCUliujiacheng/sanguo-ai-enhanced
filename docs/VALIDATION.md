# 发布前验收清单

这是维护者使用的检查清单，不是测试通过报告。每个发布版本应在 Release 中写明实际执行结果、APK SHA-256 和未覆盖范围。未执行的项目保持未勾选，并说明原因。

## 剧本数据与初始化

- [ ] 5 个原时期与 9 个新增剧本均可唯一识别，共计 14 个。
- [ ] 7 个历史剧本的年份、势力、城市和武将归属符合本版已确定的设计。
- [ ] 2 个架空剧本明确标注为架空，开局符合各自设计且可以正常展开。
- [ ] 14 个剧本均成功初始化，每个可选势力都有合法君主和可用开局城市。
- [ ] 城市、势力、武将与驻军引用有效，无一名武将同时被重复分配到多个活动部队或城市。
- [ ] 城市容量、初始金钱、士兵、武将状态等关键数值在游戏允许范围内。
- [ ] 原始地图连接保持有效，新增剧本未造成孤立出兵目标或非法城池编号。

## 时期选择与进入游戏

- [ ] Android 运行时能够找到全部 14 个剧本，标题和年份显示清楚，无缺字、重叠或不可点击的选项。
- [ ] 页面或列表切换、返回、再次进入后，选中项与实际载入剧本一致。
- [ ] 每个剧本至少选择一个势力进入地图，完成一次月份推进。
- [ ] 每个架空挑战完成开局的基本移动、战斗或其他必要操作。

## 存档与版本更新

- [ ] 新剧本保存后退出、重新启动并读取，年份、势力、城池、武将与资金保持一致。
- [ ] 读取上一版代表性存档，记录成功与否及具体兼容边界。
- [ ] 验证新 APK 与本项目上一版签名证书一致，并记录版本信息。
- [ ] 在具备可恢复测试数据的设备上验证覆盖更新；没有执行时明确写出，不能声称存档迁移已验证。

## 经济与 AI 回归

- [ ] 出征城 10000 金钱、携带 3000 后，城市 7000、部队 3000；抵达友城后总额守恒。
- [ ] 连续出征携款、余额不足、零携款和无效金额不会增加总资金。
- [ ] 玩家与电脑的携款入口均遵守相同扣款规则。
- [ ] 一名武将不会在实力与人数条件不足时被电脑派去硬攻五六名守将。
- [ ] 兵力充足时电脑能组织正常进攻，并按规则保留守军。
- [ ] 后方援军能够支援前线；抵达时守军增加会触发局势复核。
- [ ] 撤退或驻军合并不会把己方武将和金钱直接交给敌方城市。
- [ ] 原有自动战斗和玩家自主出征保持可用。

## 安装包与公开文件

- [ ] 最终 APK 完成签名、ZIP 对齐、CRC 与预期载荷校验。
- [ ] 发布附件与测试对象一致，记录并公开最终文件的 SHA-256。
- [ ] 公开仓库不包含原始 APK、全量反编译源码、工具二进制、缓存、签名私钥、个人路径或设备数据。
- [ ] README、CHANGELOG 和 Release 对已实现功能与实际测试范围的描述一致。

## 已有证据与边界

上一版经济与 AI 修改通过 29 项实际程序集行为回归，使用者已在手机上确认金钱修复生效。这些证据不替代本轮 14 个剧本的验收。

数据检查和托管逻辑测试不能证明 Android 画面、字体、触摸与存档恢复正常；APK 签名验证也不等于安装或实玩测试。Release 应分别写明这些结果。
